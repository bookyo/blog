Card 1 / The Five Headers

Five lines that decide whether you get breached

1. Content-Security-Policy (CSP)

A whitelist of allowed script, style, image, font, and frame sources. The single most powerful header on the list. A misconfigured CSP is the most common reason a stored XSS escalates from annoying to catastrophic.

2. Strict-Transport-Security (HSTS)

Tells the browser to refuse plain HTTP for a specified period. Without it, the first request after a coffee-shop captive portal can be downgraded to HTTP by an attacker on the path.

3. X-Frame-Options / frame-ancestors

Prevents your page from being embedded in an iframe on another origin -- the foundation of clickjacking. Modern CSP supersedes it, but the legacy header is still the only one some scanners check.

4. X-Content-Type-Options: nosniff

Stops the browser from MIME-sniffing a response. Without it, a text/plain response containing HTML can be rendered as HTML -- the entire premise of certain stored-XSS chains against user uploads.

5. Referrer-Policy

Controls how much of the previous page's URL is leaked in the Referer header. A token in the URL of a password-reset page is a real bug that has shipped in production more times than anyone wants to admit.
