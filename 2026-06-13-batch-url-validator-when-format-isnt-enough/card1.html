Card 1 / What "Format" Misses

Five characters a regex won't catch

1. Spaces and tabs from misquoted CSV

A field that lost its quotes preserves a trailing space: https://example.com/ . The browser refuses the parse.

2. Cyrillic homograph in the authority

A Cyrillic а in https://exаmple.com/ resolves to a different host than the user sees. Format parses. Visual layer lies.

3. Bare domains without a scheme

example.com/foo is a relative path, not a URL. Browsers resolve it against the current page. A validator that accepts it is wrong.

4. Userinfo carrying credentials

https://user:pass@example.com/ -- Chromium and Firefox strip these before the request. Any audit that flags them is doing the reader a favor.

5. Backslashes from Windows paths

https://example.com\foo parses as an authority with an invalid character. Copy-pasted through some terminals it renders as forward slashes and looks fine until inspection.
